# Apple Silicon acceleration backends for macOS

Research snapshot: 23 October 2026. Scope: local transcription acceleration in aTrain on Apple Silicon, while retaining its offline model workflow, word-level transcript output, speaker detection, and macOS 14 minimum. This is a backend evaluation, not a performance benchmark: the current environment is Linux x86_64, so no Apple hardware measurements were possible.

## Current constraints

aTrain has two transcription backends: faster-whisper/CTranslate2 and CrisperWhisper through Transformers. The regular faster-whisper path requests beam size 5, VAD filtering, initial prompts, temperature fallback, and word timestamps. The existing GPU setting is CUDA-specific: validation checks `torch.cuda`, faster-whisper selects `cuda`, and pyannote speaker detection also moves to CUDA. CTranslate2's published prebuilt GPU support lists NVIDIA CUDA; its Apple Silicon path is ARM CPU inference. Consequently, enabling the current GPU switch on a Mac cannot provide Metal acceleration.

The transcript engine normalizes output to one timestamped word per segment, then uses that representation for speaker assignment and export. Existing downloaded model folders are CTranslate2 or Transformers checkpoints. MLX and whisper.cpp require different converted model files, and WhisperKit uses Core ML packages; these cannot be treated as interchangeable files. Any new model format needs its own pinned revision and file hashes in `models.json`, integrity checks, licence/SBOM handling, and model-management behavior.

## Candidate comparison

| Candidate | Apple hardware path | Fit with current Python engine | Main benefits | Main costs and risks |
|---|---|---|---|---|
| **MLX Whisper** (`mlx-whisper`) | MLX on Apple Silicon GPU through Metal | **High.** Python API accepts NumPy audio, a local model directory, language, prompt and temperature; returns word timestamps. | Smallest integration step for Whisper. Fits the existing adapter and model-loading shape. Open source, with Apple-maintained MLX examples and community-converted checkpoints. | Needs MLX-format weights and a macOS/arm64-only dependency. The upstream implementation inspected here does not implement beam search; output quality and speed must be measured against the current beam-5 path. Word timing uses Whisper cross-attention and CPU-side Numba/SciPy processing. Model conversion, dependency resolution and PyInstaller bundling need validation. |
| **whisper.cpp** | Metal GPU; optional Core ML encoder on Apple Neural Engine | **Medium.** C API can be wrapped, or an architecture-specific helper process can expose results. | Mature C/C++ implementation, broad platform coverage, quantized models, beam search, VAD support and no Python ML framework requirement. Offers a good fallback on other platforms if aTrain later wants a shared engine. | Requires GGML-converted checkpoints and native build/binary maintenance. Word-level timestamps are documented as experimental; timing and punctuation normalization need quality checks. Core ML encoder conversion/build adds complexity and has a slow first-device compilation. A Python binding and packaged native libraries must be tested and signed. |
| **WhisperKit** (Argmax Swift SDK) | Core ML with configurable CPU, GPU and Neural Engine compute | **Medium to low.** Run a Swift helper or its local server and translate structured output into aTrain's transcript schema. | Apple-first inference; supports word and segment timestamp granularities, local model folders, language detection and prompts. The open-source SDK also offers SpeakerKit using Core ML models for diarization, which could eventually address more than ASR. Supports macOS 14. | Cross-language process/API boundary and Swift packaging add work. Models/tokenizers need to be downloaded or provisioned locally. The repository describes Pro SDK features separately, so confirm every required option is in the open-source tier. SpeakerKit would be a separate model, licence and accuracy evaluation. |
| **PyTorch MPS with Transformers** | PyTorch MPS device through Metal | **High for CrisperWhisper.** Current Transformers adapter already takes a device string and calls `.to(device)`; PyTorch supports `mps`. | Could accelerate the existing CrisperWhisper Transformers model without converting its weights or introducing a second model family. Smallest experiment for the existing Crisper model. | Not a solution for faster-whisper: CTranslate2 does not expose an MPS device. The current Crisper adapter explicitly chooses only `cuda` or `cpu`, so MPS needs a code change and runtime availability checks. PyTorch MPS operator coverage, attention capture, memory use and long-form stability need testing. CrisperWhisper is currently a limited-language model with a non-commercial research licence in this registry. |

Official implementation references: [MLX Whisper API and local/Hub models](https://github.com/ml-explore/mlx-examples/tree/main/whisper), [MLX platform requirements](https://github.com/ml-explore/mlx/blob/main/docs/src/install.rst), [whisper.cpp capabilities, Core ML and timestamps](https://github.com/ggml-org/whisper.cpp), [WhisperKit / SpeakerKit SDK](https://github.com/argmaxinc/argmax-oss-swift), [PyTorch MPS backend](https://docs.pytorch.org/docs/2.9/notes/mps.html), and [CTranslate2 hardware support](https://opennmt.net/CTranslate2/hardware_support.html).

## Recommendation

Prototype **MLX Whisper first** for the existing general Whisper models. It offers the cleanest path from the current Python transcriber contract to Metal inference, and its API already supports local MLX checkpoints, prompts, language selection, temperature and word timestamps. Keep CPU faster-whisper as the default fallback and keep the backend choice explicit. Do not infer that the speedup or transcript quality will be better until both are measured on representative Apple Silicon hardware.

Run a small **PyTorch MPS CrisperWhisper experiment in parallel** if accelerated verbatim transcription is valuable. This tests a different model and should be scored separately from regular Whisper. MPS should be selected only when `torch.backends.mps.is_available()` succeeds; it must not be routed through CUDA-specific code paths. Because the current `GPU` flag also controls diarization, separate ASR device capability from diarization device capability before exposing Apple acceleration in the UI. For an initial release, Apple-accelerated ASR can fall back to CPU diarization.

Keep **whisper.cpp as the alternative** if MLX's decoding differences, model lifecycle or packaging prove unsuitable. Its native build adds more work, but its beam search and cross-platform C API may make it a better fit where retaining decoding controls matters. Treat word timing as a release criterion because upstream labels that feature experimental. Consider WhisperKit if the project is willing to maintain a Swift bridge or local helper and wants to evaluate Core ML diarization as well as ASR. The existing Python/Transformers route is the best MPS experiment, not a general accelerator for the faster-whisper catalogue.

## Work needed for a safe comparison

Use the same audio corpus and same model family/size where possible. Record baseline CPU faster-whisper, MLX, whisper.cpp, and Crisper MPS as separate rows; Crisper is a different model and its quality numbers are not a direct backend-only comparison. Include short clean audio, long interviews, silence/noise, accented speech, multilingual audio and existing supported languages. Check word error rate, word-boundary errors, omitted/repeated speech, detected language, prompt behavior, VAD/silence handling, and transcript formatting.

Record cold model-load time, warm transcription real-time factor, peak unified memory, and failures for each machine and OS tested. Synchronize device work before stopping timers. Run repeats on at least one lower-memory and one higher-memory Apple Silicon Mac. Do not publish speed ratios without recording model quantization, decoding settings, hardware, macOS version and whether model loading is included.

Before aTrain integration, verify that the selected package resolves with the pinned project dependencies on native arm64 Python and macOS 14. Test the application from source and as a frozen `.app`; native ML libraries and their resources need to load from the bundle. Pin each converted model repository and revision, add its exact files and hashes to the model registry, and verify that inference works after downloads are complete with network access disabled. Add backend adapter tests for conversion to the existing word-segment schema, progress reporting, prompt/language settings, cleanup and graceful CPU fallback. UI work should expose an Apple-acceleration choice only on supported Apple Silicon/macOS combinations and explain when a selected model or diarization backend remains on CPU.

## Decision

Proceed to an MLX Whisper prototype plus a focused CrisperWhisper MPS smoke test. Choose the production backend only after the benchmark and frozen-app checks above. No code or dependency changes were made as part of this evaluation.
